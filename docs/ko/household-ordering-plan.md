# homecook 부부 주문 기능 계획

작성일: 2026-09-08. 기존 앱에 기능 코드를 추가했습니다.
공유 서버 배포와 두 아이폰에서의 실제 알림 수신 검증은 아직 남아 있습니다.
상세 기술 기준은 [설계 문서](../household-ordering-plan.md)에 있습니다.

현재 홈의 ‘우리집 식당’에서 메뉴판·주문함·연결 설정에 들어갑니다.
초대는 링크와 코드로 지원하며, 식당 이름·주문서·감사 반응을 포함했습니다.
개인별 별명은 후속 개선으로 남겼습니다.

## 확정한 사용 방식

- 두 사람 모두 각자 아이폰에서 사용합니다.
- 남편은 셰프, 아내는 주문하는 역할입니다. 이메일·비밀번호 입력 없이
  남편/아내를 선택하고, 처음 한 번 기기를 연결합니다.
- 기존 레시피를 메뉴판으로 사용합니다.
- 날짜와 아침·점심·저녁을 고르고 국·메인·반찬 등 여러 메뉴를 함께 주문합니다.
- 기본은 2인분이며 주문마다 인원을 변경합니다.
- 남편이 전체 주문을 접수하면 식단이 확정됩니다.
- 거절할 때는 전체 거절과 의견 남기기만 지원합니다.
- 앱을 닫아도 아이폰 알림을 받습니다.
- 공유 서버는 무료 범위에서 시작합니다.

## 실제 사용 흐름

아내가 ‘금요일 저녁, 2인, 된장국·제육볶음·나물’을 선택하고 요청을 남깁니다.
주문서를 제출하면 남편의 주문함에 들어오고 알림이 갑니다.

남편이 접수하면 기존 주간 식단의 금요일 저녁에 세 메뉴가 표시됩니다.
장보기 목록은 각 레시피의 기준 인분과 주문 인원으로 재료량을 계산합니다.
조리를 시작하고 ‘식사 준비 완료’를 누르면 아내에게 알림이 갑니다.

## 기존 앱에 붙이는 위치

| 기존 화면 | 추가되는 기능 |
|-----------|---------------|
| 홈 | 우리 식당 바로가기, 진행 중인 주문, 새 주문 수 |
| 레시피 | 메뉴판에 공개하거나 주문 불가로 바꾸기 |
| 계획 | 접수된 주문의 여러 메뉴 표시, 주문서로 이동 |
| 조리 화면 | 메뉴를 오가도 각 메뉴의 단계와 타이머 보존 |
| 설정 | 부부 연결, 초대·기기 교체, 알림, 식당 이름 |

메뉴판·주문함·주문서는 홈에서 들어가는 화면으로 추가합니다.
기존 레시피·냉장고·장보기·조리 기록 기능은 계속 사용합니다.
이번 공유 범위는 메뉴·주문·식단이며, 냉장고 재고와 장보기 체크·조리 기록은
우선 남편 기기에 유지합니다.

## 세부 운영 기본안

다음은 별도로 확답하신 요구사항이 아니라, 구현을 위한 기본 제안입니다.

- 한 날짜의 한 끼에는 진행 중인 주문 하나만 둡니다.
- 접수 전에는 아내가 수정·취소할 수 있습니다.
- 접수 후에는 취소를 요청하고 남편이 확인합니다. 메뉴를 바꾸려면 취소 후 다시 주문합니다.
- 이미 직접 적어둔 식단이 있으면 접수 전에 충돌을 보여줍니다.
  남편이 기존 식단을 정리한 뒤 접수하며, 자동 덮어쓰기는 하지 않습니다.
- 주문 시점의 메뉴 내용을 보관해 이후 레시피 수정이 지난 주문을 바꾸지 않게 합니다.
- 식당 이름, 별명, 영수증 모양 주문서, 접수 도장, 감사 반응으로 재미를 더합니다.

## 아이폰 연결과 알림

처음 한 번 초대 링크나 QR로 두 기기를 연결하고 이후 역할을 기억합니다.
휴대폰을 바꾸면 상대방 기기에서 새 초대를 발급해 연결을 복구합니다.

아이폰 알림은 iOS 16.4 이상에서 홈 화면에 추가한 웹 앱과 알림 허용이
필요합니다. 앱 안에 설치 안내·알림 허용 버튼·테스트 알림을 포함합니다.
집중 모드나 통신 상태로 알림이 늦어져도 주문함에서 상태를 확인할 수 있습니다.
근거: [WebKit 공식 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

## 개발 순서와 완료 기준

1. **부부 연결과 공유 기반**: 역할 선택, 초대, 권한, 기기 교체 복구.
2. **기존 데이터 연결**: 백업 후 메뉴·사진·기존 식단을 복사하고 검증.
3. **메뉴판과 주문**: 여러 메뉴 선택, 주문서, 접수·거절·취소 흐름.
4. **기존 조리 흐름 연동**: 식단 확정, 인분별 장보기 계산, 메뉴별 조리 상태 보존.
5. **아이폰 알림**: 새 주문·접수 결과·취소 요청·준비 완료 알림.
6. **실사용 검증**: 두 아이폰에서 앱을 닫은 상태의 알림까지 확인.

원래 데이터는 복사와 검증이 끝나기 전에 지우지 않습니다. 업로드가 끊겨도
중복 없이 재시도할 수 있게 합니다. 오프라인에서는 기존 조리와 주문 초안 작성을
지원하고, 실제 주문 제출·접수는 서버 확인을 받아야 완료로 표시합니다.

무료 서버 설정과 실제 아이폰 검증은 배포 단계에 필요합니다.
기능 완료는 두 아이폰에서 ‘주문 → 접수 → 식단·장보기 → 조리 → 준비 완료 알림’이
연결되고, 기존 백업 복원과 오프라인 조리가 정상 작동하는 것으로 판단합니다.
